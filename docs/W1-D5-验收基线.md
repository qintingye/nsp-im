### 1.2 P0 阻断缺陷定义
P0 = 满足以下任一条件，**验收直接 FAIL**：
- **数据链路崩溃**：`main_fetcher.py` 任何路径下无法运行 / 产出非法 JSON / 违反 JSON Schema
- **数据完整性破坏**：去重失效导致数据重复累积 / 来源追溯断裂
- **核心 UI 不可用**：底栏 / SVG 图 / 详情页任一在目标设备上白屏、错位不可操作
- **部署不可达**：部署产物线上无法访问，或部署后数据不更新
- **安全合规**：内网方案未审批即上公网 / 敏感信息泄露

## 五、P0/P1 风险清单（2026-08-18 预检实测）

> 来源：PM 静态审查 + 冒烟实测（.venv-d5，2026-08-18 02:4x）。**以下缺陷由 backend 在 D1-D4 中修复，D5 验收复核。**

### P0-1：CI 路径 `cd src && python main_fetcher.py` 直接崩溃（已实测复现）
- **现象**：`logging.FileHandler('logs/fetcher.log')` 在模块导入期执行，此时 `logs/` 目录未创建（`Path('logs').mkdir` 在 `__main__` 里，晚于 basicConfig）→ FileNotFoundError。
- **证据**：实测 Traceback `FileNotFoundError: ...\src\logs\fetcher.log`
- **影响**：GitHub Actions daily-fetch 必挂，E2E S1 无法通过。
- **修复方向**：模块导入期不建 FileHandler；或在 basicConfig 前 `Path('logs').mkdir(parents=True, exist_ok=True)`；或用绝对路径（相对仓库根，与 CWD 解耦）。

### P0-2：save() 相对路径错位 → 产出文件不在 CI 校验位置（代码审查确认）
- **现象**：`base.py save()` 用 `Path("data/policies.json")`（相对 CWD）。CI 先 `cd src` → 实际写入 `src/data/policies.json`（目录不存在 → 必崩）；而 CI 校验步骤读仓库根 `data/policies.json`。
- **影响**：即使 P0-1 修复，保存仍会崩溃 / 校验步骤找不到文件。
- **修复方向**：仓库根锚定（`Path(__file__).resolve().parents[1] / "data"`），CI 不 `cd src` 或统一路径。

### P0-3：id 生成违反 schema + 去重失效（已实测复现）
- **现象**：
  - 日期原始格式 `2026/08/17`（斜杠）→ id `P-NDRC-2026/08/17-4345`，**不匹配** schema pattern `^P-[A-Z]+-[0-9]+-[0-9]{4}$`；首条无日期 → `P-NDRC--8888`。
  - `hash()` 每次进程随机（PYTHONHASHSEED）→ 同一政策两次抓取 id 不同 → base.py 去重失效 → CI 每日重复累积。
  - `publish_date: "2026/08/17"` 不满足 schema `format: date`（需 ISO YYYY-MM-DD）。
- **证据**：实测 10 条 parsed，5 条 id 违反 pattern。
- **影响**：S3 校验不通过；S4 去重演示失败；数据完整性破坏。
- **修复方向**：日期标准化为 ISO（`datetime.strptime`）；id 用确定性哈希（`hashlib.sha1(title+date).hexdigest()[:4]` 或序号）；空日期兜底。

### P1-1：仓库无 remote → CI 无法推送（静态确认）
- `git remote -v` 为空。GitHub Actions 需仓库托管；Vercel PoC 也需 repo。
- **修复方向**：D1 建远程仓库并 push；CI commit/push 依赖 actions/checkout 持久凭据，需验证 GITHUB_TOKEN 写权限。

### P1-2：schema 校验未真正接入
- CI 仅 `json.load()`，未用 `jsonschema` 校验；intelligence.schema.json / scenes.schema.json 是示例文档而非 draft-07 schema。
- **修复方向**：CI 加 jsonschema 校验步骤；两文件补 `$schema/required/properties`。

### P1-3：告警仅 print，未接飞书 webhook / dead-letter queue
- base.py alert_failure 是 TODO；CI Notify 仅 echo。D3 验收项「失败告警不覆盖旧数据」需落地。

### P1-4：前端尚未进仓库（D2-D4 产出）
- 当前仓库无 index.html / manifest / sw.js。跨端回归（第二节）需等 D2-D4 前端产物。

### P1-5：内网部署审批未完成（PM Day1 待办）
- ADR-005 内网强制方案需审批；公网 Vercel 仅 PoC。D5 S6 部署目标依赖该审批。
