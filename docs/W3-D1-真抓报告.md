## 二、公共基类 `src/fetchers/robust.py` 能力清单

W3-D1 新建,封装真抓侧的横切关注点,所有 fetcher 通过多重继承复用:

### 2.1 反爬基础设施
| 能力 | 实现 | 价值 |
|------|------|------|
| 真实 UA | `ROBOT_UA = Chrome/120.0.0.0 Windows` | 通过基础 UA 校验,避免被识别为 bot |
| 完整 header 集 | 11 项 `DEFAULT_HEADERS` (Accept/Language/Encoding/Sec-Fetch-* 等) | 防止裸 `python-requests` UA 触发 403 |
| SSL 兼容 | `DEFAULT_SSL_CTX.check_hostname=False, CERT_NONE` | 解决 Windows + Py3.11 aiohttp 偶发 SSL EOF |

### 2.2 弹性重试与限流
| 能力 | 实现 | 默认值 |
|------|------|--------|
| 单次超时 | `aiohttp.ClientTimeout(total=timeout)` | 5.0s (历史 sgcc 15s → 5s) |
| 重试次数 | `max_retries` | 3 次 |
| 限流延迟 | `random.uniform(min_delay, max_delay)` | 1.0~2.0s |
| 指数退避 | `min(2**attempt, 8)` | 403/429/网络异常均触发 |
| 防冷启动 | 首次请求也加 jitter | 避免并发同瞬间请求被封 |

### 2.3 抽象与可复用接口
- `RobustFetcher` Mixin 类:`__init__()` 接收 `name/source_url/max_retries/per_attempt_timeout`,自动管理 `aiohttp.ClientSession` 生命周期
- `robust_get(url=None, *, timeout, max_retries)` 统一调用入口
- `close()` 关闭 session(由 `_run_one` finally 块保证)
- `demo_fallback()` 真抓失败兜底(子类可覆写 `_DEMO_DATA`)

### 2.4 子类接入模式
```python
class W3NdrcFetcher(NdrcFetcher, RobustFetcher):
    def __init__(self):
        NdrcFetcher.__init__(self)
        RobustFetcher.__init__(self, name=..., source_url=..., max_retries=3,
                               per_attempt_timeout=5.0)

    async def fetch_raw(self):
        html = await self.robust_get(timeout=self.per_attempt_timeout, max_retries=3)
        if html is None:
            return await super().fetch_raw()  # demo fallback
        ...
```
**优势**: 5 源共用同一套 header/SSL/重试/限流逻辑,新增源只需 ~30 行 fetch_raw。

## 三、sgcc 仍超时的根因分析 + W4 改进建议

### 3.1 现象
- 候选 URL 1: `https://www.sgcc.com.cn/` → 3×5s 全超时(~30s)
- 候选 URL 2: `https://www.sgcc.com.cn/html/sgcc_main/index.html` → 3×5s 全超时(~30s)
- 合计 ~59.4s,最终走 demo fallback(内置 4 条)

### 3.2 根因(综合证据)
1. **CDN/IP 段封禁**: sgcc.com.cn 部署在 Cloudflare/自建 CDN,对境外 IP(本机出口疑似非中国 IP)长期 524/TCP 黑洞。
   - 验证:浏览器直访亦缓慢,但 curl 加 `--resolve` 直连 IP 可显著快。
2. **TLS 协商卡顿**: SNI/CDS 检查可能 hang 在 SSL handshake。
4. **JS 渲染门控**: 首页 `index.html` 大量内容由前端 JS 注入,静态 HTML 解析得 0 条(本轮 fetch_raw 已试,但被 SSL/超时拦截在更上游)。
3. **a 个例限流**: sgcc 反爬对单 IP 单 UA 频次敏感,即使 1-2s jitter 仍可能触发 token 失效。

### 3.3 W4 改进建议(优先级排序)
| P | 方案 | 工作量 | 预期收益 |
|---|------|--------|----------|
| **P0** | **接入代理池/出口切换**(国内云函数/Azure 香港等) | 1d | sgcc 成功率 0% → 80%+ |
| **P1** | **Playwright headless fallback**(针对 sgcc 等 JS 渲染站) | 2d | 静态 HTML 抓不到的站全覆盖 |
| **P2** | **真实 RSS/订阅源**(sgcc 官网提供 RSS 接口) | 0.5d | 绕开 HTML 反爬 |
| **P3** | **二级 URL 探测**(从其它页找 sgcc 子域/镜像,如 `news.sgcc.com.cn`) | 0.5d | 备选通道 |
| **P4** | **TLS 指纹伪装**(curl_cffi 替代 aiohttp) | 0.5d | 通过基础 TLS 校验 |

**建议 W4 启动先做 P0**:接 1-2 个国内 HTTP 代理(免费 IP 池即可),sgcc fetcher 加 `aiohttp-socks` 走代理,验证是否回归 100%。若仍超时,叠加 P2 RSS。

### 3.4 当前缓解(已生效)

- `w3d1_summary.json` 显式标记 `fallback=true`,便于监控告警
