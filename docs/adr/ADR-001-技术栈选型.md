# ADR-001 · 技术栈选型

> **状态**：已接受（2026-08-18）｜**类型**：架构决策
> **作者**：PM｜**关联**：ADR-002/003/004

## 背景
NSP-IM 六网协同情报平台需在 8 周内交付 MVP，面向 25-30 人内部团队使用，移动端优先（iOS Safari / Android Chrome / PC），0 现金投入。

## 决策
| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | 纯 HTML/CSS/JS + PWA（无框架） | 单文件回归面小、零依赖、可静态托管 |
| 后端 | Python 3.11 + aiohttp + BeautifulSoup | 抓取生态成熟、异步并发、无运维成本 |
| 数据 | Git 仓库内 JSON 文件（policies.json / intelligence/ / cases/） | 版本可追溯、原子提交、天然回滚 |
| CI | GitHub Actions（daily-fetch.yml，每日 09:00） | 免费、定时抓取→校验→commit→push 闭环 |
| 托管 | 内网部署（主）+ Vercel 公网 PoC（备） | 政策数据合规要求内网强约束（见 ADR-005） |

## 后果
- 前端无构建链 → 改动即生效，但需自约束代码质量（W1 拆细任务逐项验收）
- 数据即文件 → 需原子写入防半写（ADR-003 已含 tmp+rename）

## 备选
- Vue/uni-app：生态成熟但需构建链，W1 时间窗内风险高 → 否决
- 数据库（SQLite/Postgres）：MVP 阶段过度设计 → 推迟到 W2 按需引入
